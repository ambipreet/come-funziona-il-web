1. Le basi teoriche del Web

Come comunicano i dispositivi in rete e quali regole usano per scambiarsi pagine web ed email.

1.1 Modello Client-Server e Stack TCP/IP

Il Web funziona secondo il modello Client-Server:

  • Client: è il programma che richiede un servizio (es. il tuo browser Chrome, Safari o Firefox su PC o smartphone).
  • Server: è un computer sempre acceso e connesso a Internet che ospita i file dei siti web e risponde alle richieste dei client.

Per comunicare, client e server usano una pila di regole chiamata Stack TCP/IP (composta da 4 livelli). Noi ci concentriamo sul Livello Applicativo, quello più vicino all'utente, che si appoggia ai livelli sottostanti per far viaggiare i dati in rete:

4. Livello Applicazione (HTTP, HTTPS, DNS, SMTP, IMAP) → Il nostro focus!
3. Livello Trasporto (TCP / UDP) → Suddivide i dati in pacchetti e controlla gli errori
2. Livello Internet (IP) → Indirizza i pacchetti verso la destinazione corretta
1. Livello Accesso alla Rete (Ethernet, Wi-Fi) → Trasmette i bit fisici

1.2 Anatomia di un URL e risoluzione DNS

Un URL (Uniform Resource Locator) è l'indirizzo unico di una risorsa sul Web. Ecco da cosa è formato:

https:// www.esempio.it /articoli/rete.html
  • Protocollo (https://): indica le regole da usare per comunicare.
  • Nome di dominio (www.esempio.it): il nome leggibile del server.
  • Percorso (/articoli/rete.html): la posizione specifica del file sul server.

Il ruolo del DNS (Domain Name System): I computer in rete non capiscono i nomi come www.esempio.it, ma usano numeri chiamati indirizzi IP (es. 93.184.216.34). Il DNS funziona come una gigantesca rubrica telefonica distribuita: quando digiti un indirizzo, il browser interroga un resolver DNS per tradurre il nome di dominio nel corrispondente indirizzo IP.

1.3 HTTP, Metodi, Status Code e HTTPS (TLS)

HTTP (HyperText Transfer Protocol) è il protocollo con cui browser e server si scambiano pagine web tramite messaggi di Richiesta (Request) e Risposta (Response).

Esempio di Richiesta HTTP:
GET /index.html HTTP/1.1
Host: www.esempio.it

Esempio di Risposta HTTP:
HTTP/1.1 200 OK
Content-Type: text/html

Metodi principali: GET serve per chiedere e leggere una risorsa (es. aprire una pagina); POST serve per inviare dati al server (es. compilare un modulo di login).

Codice di stato Significato Cosa è successo
200 OK Successo Il server ha trovato la risorsa e l'ha inviata al browser.
403 Forbidden Accesso negato Il server ha capito la richiesta, ma non hai i permessi per vedere la pagina.
404 Not Found Non trovato L'indirizzo inserito non corrisponde a nessuna pagina sul server.
500 Internal Server Error Errore del server Il server ha avuto un problema interno e non riesce a rispondere.

Perché serve HTTPS con TLS? Il normale HTTP invia i dati "in chiaro": chiunque intercetti la rete (es. su un Wi-Fi pubblico) potrebbe leggere password o messaggi. HTTPS aggiunge il protocollo crittografico TLS (Transport Layer Security), che cifra i dati rendendoli illeggibili agli estranei e verifica l'identità del server tramite certificati digitali (il lucchetto nel browser).

1.4 Oltre il Web: la posta elettronica (SMTP e IMAP)

Il livello applicativo non gestisce solo pagine web. Quando invii o leggi un'email entrano in gioco altri protocolli:

  • SMTP (Simple Mail Transfer Protocol): si occupa esclusivamente di inviare l'email dal tuo client al server di posta e di inoltrarla fino al server del destinatario.
  • IMAP (Internet Message Access Protocol): permette al tuo dispositivo di leggere e sincronizzare le email direttamente sul server, mantenendo cartelle e messaggi aggiornati su smartphone, tablet e PC.
